# Watchlist

Личная медиатека для фильмов, сериалов, аниме, дорам, мультфильмов и BL / лакорнов.

**Сайт:** [watchlist-75e.pages.dev](https://watchlist-75e.pages.dev/)
**Репозиторий:** [Rakhimova-Z/watchlist](https://github.com/Rakhimova-Z/watchlist)

## Возможности

- Поиск в TMDB прямо в библиотеке. При единственном точном совпадении тайтл добавляется в очередь; иначе предлагается выбор. Повторное добавление показывает текущий статус и кнопку открытия карточки.
- Автоматическое заполнение постера, года, описания, жанров, стран и доступных сведений о длительности, сезонах и сериях.
- Редактирование названия, категории, статуса, оценки 1–10, даты просмотра и заметок. Удаление с подтверждением.
- Для сериалов на паузе и брошенных — необязательные сезон и серия, на которых остановлен просмотр. Для фильмов — время в формате ЧЧ:ММ:СС. При смене статуса сохранённая отметка не удаляется.
- Избранное и отдельные отметки «Хочу пересмотреть» / «Пересматриваю» без изменения основного статуса, оценки и даты.
- Личные типы: можно добавлять свои и убирать стандартные, BL / лакорны больше не входят в стандартные разделы; существующие коллекции сохранены как личный тип. После удаления типа тайтлы остаются в «Без типа»; стандартный тип можно вернуть. Порядок разделов настраивается для каждого аккаунта.
- Свои списки и теги: тайтл может входить в несколько списков и иметь несколько тегов. Назначение — в карточке, создание списков — в настройках. Удаление списка не удаляет тайтлы. Теги вводятся через запятую, нормализуются в нижний регистр и не дублируются.
- Дневник просмотров: отдельная дата, оценка, заметка и признак пересмотра для каждого события. Записи можно менять и удалять; основные поля карточки остаются прежними.
- Статистика дневника: просмотры по месяцам, распределение оценок событий и жанров, число пересмотров и уникальных тайтлов. Есть выбор года. Завершение через статус учитывается автоматически. Старые просмотренные тайтлы перенесены без дублирования дневника; неизвестные даты входят только в общий итог.
- Сворачиваемые разделы или общий список, фильтры по собственным спискам и тегам.
- Поиск по библиотеке и фильтры по статусу, категории, жанрам, годам выхода, длительности, пересмотру и избранному. Несколько жанров объединяются по условию «любой из выбранных».
- Сортировка по дате добавления, году выхода, дате просмотра, общему времени, алфавиту и оценке в обоих направлениях. Неизвестные значения идут последними.
- Кнопка «Выбери за меня»: случайный тайтл из очереди, а если очередь пуста — из библиотеки.
- Вход по ссылке из письма; пароль и уникальное имя пользователя — необязательны. Настройки и библиотека синхронизируются между устройствами.

## Как устроен проект

Статический HTML/CSS/JavaScript без сборки. Cloudflare Pages публикует frontend из ветки `main`; Supabase отвечает за авторизацию и данные; TMDB вызывается через серверную Edge Function.

| Файл / каталог | Назначение |
| --- | --- |
| `index.html` | Интерфейс, формы и диалоги |
| `styles.css` | Тёмная тема и адаптивная вёрстка |
| `app.js` | Авторизация, библиотека, настройки и взаимодействие с Supabase |
| `duration.mjs` | Расчёт и форматирование длительности |
| `personal-library.mjs` | Личные типы, теги и расчёт статистики дневника |
| `diary-ui.mjs` | Создание и редактирование истории просмотров, графики |
| `library-order.mjs` | Сортировка, фильтрация по жанрам и годам |
| `config.js` | Публичный URL Supabase и publishable key |
| `supabase/migrations/` | Версионируемые изменения схемы и прав доступа |
| `supabase/functions/tmdb/` | Поиск и получение сведений о тайтлах |
| `supabase/functions/username-login/` | Проверка имени и пароля через Supabase Auth |
| `supabase/config.toml` | Настройки развёртывания функции входа |
| `tests/` | Логические и браузерные проверки |

## Данные и доступ

- `watchlist_items`: записи пользователя, сведения TMDB, личные поля, избранное, пересмотр и место остановки брошенного сериала.
- `watchlist_profiles`: уникальное имя, порядок разделов, личные типы, скрытые стандартные типы и списки. Браузер может читать и менять только профиль текущего пользователя.
- `watchlist_entries`: независимые записи просмотров с привязкой к владельцу и его тайтлу. Составной внешний ключ не позволяет связать запись с чужим тайтлом. Удаление тайтла удаляет его историю после подтверждения в интерфейсе.
- `username_login_limits`: серверные счётчики попыток входа по имени. Браузеру доступ запрещён.

На таблицах включён RLS. Запросы к библиотеке дополнительно ограничиваются текущим `user_id`. Имя не используется для определения прав доступа: после проверки пароля приложение работает с обычной сессией Supabase.

`username-login` принимает запросы без готовой сессии, проверяет пароль через Supabase Auth и возвращает токены только после успешного входа. Email по имени не выдаётся. Ограничения: 15 попыток на имя и 300 суммарно за 15 минут. Вход по ссылке и email остаётся доступен отдельно.

Секрет `TMDB_ACCESS_TOKEN` хранится только в Supabase. Серверная функция входа использует `SUPABASE_SERVICE_ROLE_KEY` из окружения Edge Functions. **Секретные ключи и пароли нельзя добавлять во frontend, Git или логи.** Ключ в `config.js` публичный; защита данных обеспечивается RLS.

## Локальный запуск

Из корня репозитория:

```sh
python3 -m http.server 8000
```

Открыть [localhost:8000](http://localhost:8000). Сборка не требуется. Для входа по ссылке локальный адрес должен быть разрешён в Supabase Auth → URL Configuration → Redirect URLs.

**Важно:** текущий `config.js` подключён к рабочему Supabase. Редактирование и удаление тайтлов при локальном запуске меняют настоящую библиотеку. Для разработки с изолированными данными используйте отдельный проект Supabase.

## Подключение нового окружения

1. Создать Supabase-проект и применить SQL из `supabase/migrations/` по порядку: сначала `001_watchlist.sql`, затем файлы с временными метками. Не запускать уже применённые миграции повторно.
2. Убедиться, что таблицы доступны через Data API, а роли `authenticated` выданы `SELECT`, `INSERT`, `UPDATE`, `DELETE` для `watchlist_items`. RLS должен оставаться включённым.
3. Указать URL и публичный ключ в `config.js`. Название параметра `SUPABASE_ANON_KEY` сохранено для совместимости; в нём используется publishable key.
4. Сохранить `TMDB_ACCESS_TOKEN` в Edge Function Secrets. Развернуть обе функции из `supabase/functions/`. Для `tmdb` требуется пользовательская сессия; для `username-login` проверка JWT шлюзом отключена в `supabase/config.toml`, поскольку функция сама проверяет пароль.
5. Включить email-авторизацию. Настроить Site URL и разрешённые Redirect URLs под адрес сайта. Для надёжной доставки писем настроить SMTP.
6. Войти по ссылке. При желании задать пароль и имя в разделе «Аккаунт».

Для текущего production используется Supabase-проект `hhsnsnjipggvndycvqjt`. Site URL — `https://watchlist-75e.pages.dev`, Redirect URL — `https://watchlist-75e.pages.dev/`.

## Проверки

Логические проверки выполняются в Node.js без дополнительных пакетов:

```sh
node --check app.js
node tests/duration.mjs
node tests/library-order.mjs
node tests/personal-library.mjs
git diff --check
```

Браузерный тест использует Playwright и установленный Google Chrome:

```sh
npm install --no-save --package-lock=false playwright@1.62.1
node tests/watchlist.cjs
```

Если Playwright установлен вне проекта, задайте `NODE_PATH` к каталогу с пакетами. Тест подменяет Supabase и TMDB: проверяет интерфейс, ошибки, формы входа, фильтры, сортировку, сохранение и удаление на тестовых данных, не изменяя production. Снимки проверяемых экранов сохраняются в `/tmp/watchlist-*.png`.

Браузерная подмена API хранится в `tests/mock-supabase.mjs`. Дневник загружается страницами, поэтому статистика не ограничивается первой тысячей записей.

Эти тесты не заменяют проверку миграций, RLS и Edge Functions в целевом Supabase-проекте.

## Публикация

Cloudflare Pages подключён к GitHub и автоматически запускает деплой после push в `main`:

- Framework preset: **None**.
- Build command: пусто.
- Build output directory: `/`.

Изменения БД и Edge Functions нужно применять в Supabase отдельно, **до** публикации интерфейса, который на них опирается. Push в GitHub не применяет миграции и не развёртывает Edge Functions. После публикации следует проверить статус деплоя Cloudflare и обновлённый сайт.

## Ограничения данных

- Дата выхода пока хранится только как год.
- «Основной жанр» на карточке — первый жанр из TMDB.
- Общее время сериала оценивается как число всех серий × длительность одной серии. Сезоны повторно не умножаются. Если длительность неизвестна, показывается количество серий, когда оно доступно; иначе подпись скрывается.
- Поиск пока показывает до 12 результатов с первой страницы TMDB. Русские переводы могут отличаться: при пустом результате интерфейс предлагает другое название или язык.
- Категория определяется автоматически и может быть исправлена вручную. Надёжного автоматического определения BL нет.

### Правила дневника и личной организации

- Списки и пользовательские типы имеют стабильные идентификаторы в профиле. Названия не используются как ссылки на тайтлы. Метки удалённых списков в записи тайтла игнорируются и очищаются при следующем сохранении карточки; ссылки на удалённый тип показываются как «Без типа».
- Фильм/сериал (`media_type`) остаётся справочным признаком TMDB, независимо от личного типа. Исходная категория TMDB сохраняется для совместимости.
- В дневник записывается завершённый просмотр всего тайтла; для ручных записей пользователь отмечает пересмотр, кнопка завершения пересмотра создаёт событие автоматически. Два просмотра одного тайтла в один день требуют явного подтверждения при ручном добавлении. Повторная отправка одной формы после сетевого сбоя использует тот же UUID и не создаёт второй экземпляр события.
- Оценки в статистике берутся из записей дневника, а не из текущей оценки карточки. Жанры — из текущих сведений о тайтле; каждый жанр считается отдельно и каждый пересмотр учитывается вновь. Отсутствующая оценка не считается нулём.

- Счётчики библиотеки работают как быстрые фильтры по статусу (включая «Паузу»). «Всего» снимает фильтр статуса; остальные выбранные параметры сохраняются.
- В аккаунте можно необязательно указать пол для подписей «посмотрел / посмотрела» и «бросил / бросила». Без выбора используются нейтральные подписи.

### Автоматическая история

Серверный триггер в одной транзакции со сменой статуса сохраняет добавление тайтла, смены статуса и отметки пересмотра. Только завершённые просмотры входят в статистику. Повторное сохранение или переключение уже просмотренного тайтла не создаёт новый просмотр: для этого есть «Завершить пересмотр». Дневник необязателен; общий показывает все события, история из карточки ограничена её тайтлом. Автоматическую запись можно дополнить датой, оценкой и заметкой.

Место остановки проверяется по данным тайтла: сезон и число серий этого сезона загружаются из TMDB; время фильма ограничено его длительностью. При отсутствии точных данных можно сохранить пустую отметку. Избранное переключается сердечком, без дублирования в форме. Поле пересмотра показывается только при статусе «Просмотрено»; скрытые старые отметки сохраняются.
